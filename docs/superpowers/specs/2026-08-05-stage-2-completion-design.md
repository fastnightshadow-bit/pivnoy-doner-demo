# Завершение второго этапа «Пивной Донер»

## Цель

Довести локальную демонстрационную версию клиентского приложения, кухни и интерфейса курьера до согласованного состояния второго этапа, проверить основные сценарии и затем опубликовать обновление на GitHub Pages для показа владельцу.

Второй этап остаётся демонстрацией интерфейсов и бизнес-логики в браузере. Настоящая база данных, серверная авторизация, ЮKassa, реальные уведомления и административная панель относятся к третьему этапу.

## 1. Платные соусы

- В карточке каждого блюда показывается раздел «Соусы» в утверждённом варианте A: компактные текстовые карточки без фотографий.
- В карточке слева находится название, справа — `+50 ₽`.
- Можно выбрать несколько соусов одновременно.
- При открытии карточки ни один соус не выбран.
- Нажатие выбирает соус, повторное нажатие снимает выбор.
- Выбранное состояние обозначается аккуратной рамкой, галочкой или нейтральным контрастом из действующей дизайн-системы; карточка не заливается большим красным блоком.
- Каждый выбранный соус увеличивает цену одной позиции на 50 ₽. Например, два соуса добавляют 100 ₽.
- Цена в закреплённой нижней панели пересчитывается мгновенно.

В данных новая позиция хранит массив `sauces`. Для совместимости старая строка `sauce` при чтении преобразуется в массив из одного элемента, поэтому уже созданные локальные позиции корзины не ломаются.

Выбранные соусы отображаются в:

- корзине;
- оформлении заказа и сохранённом заказе;
- активном заказе;
- карточке заказа кухни.

Список соусов: Тейсти, Бургерный, Сырный, Барбекю, Трюфель, Кетчуп, Карри, Блю чиз, Горчица, Чили. Цена каждого — 50 ₽.

## 2. Добавки

- Добавка называется «Жареный лук», не «Лук».
- Остальные существующие добавки и их цены не меняются.
- Добавки и соусы остаются разными группами: добавки меняют состав блюда, соусы выбираются отдельно.

## 3. Кухня

- Для демонстрации используется один общий вход кухни вместо личных аккаунтов сотрудников.
- Интерфейс не просит выбрать конкретного повара: на смене всегда два повара.
- Действия в истории подписываются общим именем «Кухня».
- Кухня и продавец могут ставить блюда в стоп-лист и временно включать или выключать приём заказов.
- Изменение цен, состава меню и рецептуры в интерфейс второго этапа не входит.
- Существующие безопасные переходы статусов, отмена заказа, защита от двойного нажатия и отображение ошибок сохраняются.

## 4. Расчёт времени приготовления

Расчёт для демонстрации строится по очереди шаверм и мощности кухни:

- два повара работают одновременно;
- один повар может готовить до трёх шаверм в одном цикле;
- один цикл занимает примерно 8 минут;
- общая мощность одного цикла — до 6 шаверм;
- 1–6 шаверм дают ориентир 8 минут, 7–12 — 16 минут, 13–18 — 24 минуты и далее;
- к новому заказу применяется уже занятая очередь активных заказов;
- результат является ориентировочным временем, а не обещанием точности до минуты.

Обычные блюда без количества шаверм не должны увеличивать расчёт как полноценная шаверма. Для неизвестных данных используется безопасный минимальный ориентир.

## 5. Курьер

- Временный курьер демонстрации — Павел, владелец ресторана.
- После входа интерфейс показывает только нужные курьеру данные: через сколько будет готов заказ, адрес доставки и контакт клиента.
- Нажатие на телефон открывает системное подтверждение звонка.
- Курьер видит только оплаченные заказы с доставкой и допустимым активным статусом.
- PIN остаётся только демонстрационным. В третьем этапе он будет храниться на сервере и не будет виден в клиентском коде.

## 6. PWA и фирменные иконки

- Клиентское приложение, кухня и курьер сохраняют отдельные PWA-манифесты.
- Во вкладке браузера и при добавлении на домашний экран используется оригинальный фирменный логотип, а не буква «П».
- Проверяются размеры favicon, Apple Touch Icon и PWA-иконок 192/512 px.
- После публикации старый ярлык на iPhone может потребоваться удалить и добавить заново из-за кеша iOS.

## 7. Проверка

Автоматические тесты должны подтвердить:

- отсутствие выбранных соусов по умолчанию;
- выбор нескольких соусов и прибавление 50 ₽ за каждый;
- совместимость со старым полем `sauce`;
- сохранение соусов в корзине, заказе и кухне;
- корректные границы расчёта 1–6, 7–12 и следующих партий;
- общий кухонный аккаунт и имя «Кухня» в истории;
- имя Павел в демонстрационном интерфейсе курьера;
- наличие и размеры PWA-иконок.

Ручная проверка выполняется на мобильной ширине для клиента и курьера, а также на планшетной ширине для кухни. Проверяются светлая и тёмная темы, карточка блюда, корзина, оформление, кухня и установка PWA.

## 8. Публикация

После успешных тестов изменения публикуются в репозитории GitHub и на GitHub Pages. Публичная версия остаётся демонстрационной: она не принимает настоящие платежи и не отправляет реальные заказы на сервер ресторана.

## Не входит во второй этап

- административная панель владельца;
- настоящая серверная база данных;
- настоящие аккаунты и роли;
- реальная интеграция ЮKassa;
- реальные push-уведомления;
- перенос на `pivdoner.ru` и поддомены;
- отключение существующего Telegram-бота;
- продакшен-настройка RUVDS и юридических документов.

Эти задачи выполняются в третьем этапе после окончательного согласования демонстрации владельцем.
