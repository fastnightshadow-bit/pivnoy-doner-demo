# Фоновые push-уведомления курьеру — проект решения

## Цель

Курьер должен получить одно уведомление о новом оплаченном заказе с доставкой, даже если PWA «Курьер» свёрнута или закрыта. Нажатие на уведомление открывает рабочее приложение курьера.

## Выбранный подход

Используется стандартный Web Push с VAPID-ключами и надёжной серверной очередью. Внешний сервис Firebase не нужен. Закрытая вкладка не участвует в доставке: уведомление принимает service worker установленной PWA.

## Пользовательский сценарий

1. Курьер входит по PIN и один раз нажимает «Включить уведомления».
2. Браузер запрашивает системное разрешение.
3. PWA создаёт push-подписку и передаёт её авторизованному API.
4. После успешной оплаты заказа с доставкой сервер атомарно создаёт задание на push.
5. Фоновый обработчик отправляет уведомление всем активным устройствам курьерского аккаунта.
6. Уведомление показывает номер заказа, время готовности и адрес. Телефон клиента остаётся внутри приложения.
7. Нажатие открывает или активирует `courier.pivdoner.ru/courier.html`.

Push отправляется только один раз на новый оплаченный заказ доставки. Заказы самовывоза и неподтверждённые платежи уведомление курьеру не создают.

## Серверная архитектура

В PostgreSQL добавляются две таблицы:

- `push_subscriptions` — подписка устройства, привязанная к аккаунту курьера; endpoint уникален, ключи хранятся только на сервере;
- `push_jobs` — очередь уведомлений с уникальностью по типу события и заказу, количеством попыток и временем следующей попытки.

При подтверждении оплаты уже существующая транзакция создаёт задание `courier.order_paid`, только если заказ имеет способ получения `delivery`. Это защищает от потери события между фиксацией оплаты и отправкой push.

Фоновый обработчик запускается внутри API-процесса, забирает доступные задания с блокировкой `FOR UPDATE SKIP LOCKED`, отправляет их через библиотеку `web-push` и фиксирует результат. Временные ошибки повторяются с ограниченной задержкой. Ответы push-сервиса 404/410 деактивируют устаревшую подписку. Ошибка отправки никогда не отменяет подтверждённую оплату.

## API и безопасность

- `GET /api/push/public-key` — публичный VAPID-ключ;
- `POST /api/push/subscriptions` — создать или обновить подписку; доступ только ролям `courier` и `owner`;
- `DELETE /api/push/subscriptions` — удалить подписку текущего устройства при выходе.

API валидирует endpoint и криптографические ключи, не возвращает их в клиентские ответы и не пишет их в журнал. Приватный VAPID-ключ хранится только в серверном `.env`, не попадает в GitHub или HTML.

## Клиент и service worker

`courier.js` регистрирует service worker, преобразует публичный VAPID-ключ, создаёт `PushManager`-подписку и синхронизирует её с сервером. При последующих входах уже разрешённая подписка восстанавливается автоматически.

`courier-sw.js` получает событие `push`, показывает системное уведомление и использует стабильный `tag` заказа, чтобы дубликаты заменялись. Обработчик `notificationclick` сначала пытается активировать существующее окно курьера, а затем открывает новое. Демонстрационный параметр `?demo=1` в производственной ссылке не используется.

Текущая SSE-синхронизация остаётся для открытого приложения. Локальное уведомление открытой страницы отключается после успешной Web Push-подписки, чтобы курьер не получал два одинаковых уведомления.

## Совместимость

- Android: Chrome/Edge и установленная PWA поддерживают фоновые уведомления.
- iPhone: требуется iOS 16.4 или новее и добавление сайта на экран «Домой» до запроса разрешения.
- Пользователь должен один раз вручную разрешить уведомления; браузер не позволяет обойти этот шаг.

## Ошибки и восстановление

- Нет разрешения: приложение показывает понятную кнопку включения, остальная работа курьера не блокируется.
- Нет VAPID-конфигурации: API отвечает контролируемой ошибкой, а основной заказ продолжает работать.
- Временная ошибка push-провайдера: задание повторяется.
- Подписка удалена браузером: сервер деактивирует её после ответа 404/410.
- Повторный webhook оплаты: уникальность задания не допускает повторного push.

## Проверка

Автоматические тесты должны подтвердить:

- подписку может сохранить только курьер или владелец;
- некорректная подписка отклоняется;
- оплаченный заказ доставки создаёт ровно одно задание;
- самовывоз и неоплаченный заказ не создают задание;
- временная ошибка повторяется, а 404/410 удаляет подписку;
- service worker показывает уведомление и правильно открывает приложение;
- выход удаляет подписку устройства;
- файл Яндекс Вебмастера существует в корне и содержит точный код проверки.

Перед выпуском выполняются клиентские и серверные тесты, проверка production-сборки, тестовая подписка на телефоне и один контролируемый тестовый заказ доставки.

## Развёртывание

Для stage и production создаются разные пары VAPID-ключей. Миграции применяются автоматически при запуске API. Сначала изменение проверяется на `stage.pivdoner.ru`, затем тем же коммитом разворачивается на основном сервере. Приватные ключи передаются только в серверные `.env`.
