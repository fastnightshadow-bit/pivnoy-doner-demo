# Публичный стоп-лист — дизайн исправления

## Цель

Связать стоп-лист кухни с клиентским приложением, не меняя оплату и другие рабочие процессы. Недоступное блюдо остаётся видимым, получает отметку «Нет в наличии» и не может попасть в новый заказ.

## Поток данных

1. Кухня и владелец продолжают сохранять доступность товара в таблице `catalog_products`.
2. Новый публичный read-only API возвращает только состояние приёма заказов и массив идентификаторов недоступных товаров. PIN, сотрудники и внутренние настройки в ответ не попадают.
3. Клиент загружает состояние при открытии и обновляет его по безопасному периодическому запросу и при возвращении вкладки на экран.
4. Карточки и нижняя панель блюда используют единый набор недоступных идентификаторов.
5. Сервер создания заказа повторно сверяет все позиции с базой перед расчётом и сохранением.

## Клиентское поведение

- Недоступная карточка остаётся на своём месте и выглядит приглушённо.
- На ней отображается «Нет в наличии» вместо кнопки добавления/счётчика.
- Открыть карточку можно для просмотра, но нижняя кнопка покупки заблокирована и объясняет причину.
- Если товар уже лежит в корзине и позже попал в стоп-лист, оформление блокируется с понятным сообщением. Корзина не удаляется автоматически.
- При сетевой ошибке клиент не объявляет товар доступным заново: сохраняется последнее успешно полученное состояние в памяти текущей вкладки, показывается ненавязчивое уведомление при попытке оформить заказ.

## Серверная защита

- Публичный endpoint не требует входа и возвращает минимальный ответ без персональных данных.
- Создание заказа отклоняется до расчёта цены, если хотя бы один товар находится в стоп-листе.
- Ошибка содержит стабильный код и список только идентификаторов недоступных товаров, чтобы клиент мог подсветить позиции.
- Неизвестные идентификаторы товаров по-прежнему отклоняются существующей проверкой каталога.

## Обновление

- После события `settings.updated` клиент может сразу перечитать публичный статус, если SSE доступен.
- Резервный вариант — небольшой polling и обновление при `visibilitychange`.
- Запросы не должны накладываться друг на друга, а таймер очищается при выгрузке страницы.

## Тестирование

- Публичный endpoint не раскрывает внутренние поля.
- Клиент отображает и блокирует недоступный товар.
- Возврат товара из стоп-листа восстанавливает кнопку.
- Уже добавленный недоступный товар блокирует checkout без потери корзины.
- Сервер отклоняет прямой или устаревший запрос с недоступным товаром.
- Остальные клиентские и серверные тесты проходят без изменений оплаты.

## Вне объёма

- Подключение ЮKassa и тестовая оплата.
- Изменение кухни, ролей, PIN и панели владельца.
- Скрытие блюд из каталога.
- Автоматическая замена или удаление позиций из корзины.
