# Обращение покупателя по персональным данным

Все запросы на доступ, исправление, блокирование, удаление данных или снятие отзыва направляются на `Piv.don@ya.ru`. Не переносите текст обращения в общий чат, консоль или обычные логи сайта.

## 1. Принять и зарегистрировать

В закрытом реестре создать номер дела и зарегистрировать дату получения, канал, вид запроса, контрольный срок, ответственного, статус проверки, выполненное действие и дату закрытия. Не копировать содержание обращения в общий лог; телефон, адрес, комментарий, токен и паспортные данные там тоже не фиксировать.

Владелец определяет применимый срок и основания ответа с профильным юристом. Автоматически обещать удаление нельзя: часть платёжных и договорных сведений может требовать хранения.

## 2. Проверить личность и заказ

1. Запросить номер заказа и телефон, использованный в заказе. Не просить секретный токен из браузера, PIN сотрудника, данные карты, паспорт или фотографию документа без отдельной правовой необходимости.
2. В защищённом интерфейсе сверить номер заказа и телефон. Для дополнительной проверки позвонить по телефону, уже записанному в заказе, и уточнить нейтральный факт заказа; не раскрывать сведения первым.
3. Для отзыва также проверить связь отзыва с завершённым заказом.
4. В закрытом реестре отметить только метод, дату и результат проверки личности/номера заказа. Не записывать ответы проверки и содержимое заказа.
5. Если проверка не пройдена, не выдавать и не менять данные; объяснить, какой безопасный шаг проверки нужен.

## 3. Найти данные

Технический администратор ищет по внутреннему id/номеру заказа в `orders`, `order_items`, `payments`, `reviews` и `status_history`. Результат не выгружается в общий файл. Передача покупателю содержит только его данные и безопасный формат без внутренних хэшей, секретов, сведений сотрудников и других покупателей.

## 4. Снять отзыв с публикации

1. После проверки найти `review_id` по заказу.
2. Технический администратор выполняет штатную операцию `reviews.unpublish(id, revokedAt)`. Если требуется аварийная работа в БД — только в транзакции и с параметром, без вставки текста обращения:

   ```sql
   update reviews
   set published = false, publication_revoked_at = now()
   where id = :review_id
   returning id, published, publication_revoked_at;
   ```

3. Проверить, что `published = false` и отзыв исчез из публичного `/api/reviews`.
4. Не удалять доказательство согласия сразу: автоматическое удаление сработает через 3 года после отзыва согласия.

## 5. Обезличить закрытый заказ

Досрочное обезличивание выполняется только после решения владельца о правовом основании и обязательных сроках хранения. Сначала сделать резервную копию и определить связанные платёж/отзыв. Открытый заказ не обезличивать.

Администратор использует параметризованную транзакцию для одного `:order_id`:

```sql
begin;
update orders
set customer_name = '', phone = '', address = '{}'::jsonb,
    customer_comment = '', courier_comment = '', access_token_hash = null
where id = :order_id and status in ('completed', 'cancelled')
returning id, status;
update status_history
set actor_id = null, actor_name = 'Сотрудник', reason = ''
where order_id = :order_id;
update payments set provider_payload = '{}'::jsonb where order_id = :order_id;
commit;
```

Позиции, суммы и минимальные платёжные сведения не удалять без решения владельца/юриста. Связанный отзыв обработать отдельно: снять с публикации либо удалить/обезличить, если для этого подтверждено основание.

После операции проверить пустые поля выборкой только по `id`; не печатать старые значения. Учесть, что очистка `access_token_hash` прекращает доступ покупателя к странице этого заказа.

## 6. Плановая очистка

Для обычных сроков сначала запустить retention с `--dry-run`, сохранить только агрегатные количества, проверить их и только затем запускать `--apply`. Эти команды обрабатывают все записи, достигшие срока, и не подходят как единственный шаг для срочного индивидуального обращения.

## 7. Ответ и закрытие

Ответить с `Piv.don@ya.ru`: что сделано, что сохранено и на каком основании, как обжаловать результат. В закрытом реестре отметить срок и действие без копирования текста ответа. Закрыть дело после технической проверки и подтверждения отправки.
