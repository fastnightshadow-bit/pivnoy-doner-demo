# Чек-лист ЮKassa, ККТ и электронного чека

Статус: live-режим заблокирован. В конфигурации запуска остаётся `PAYMENT_PROVIDER=mock`; рабочие реквизиты отсутствуют. Код не подтверждает регистрацию ККТ и не заменяет настройку в кабинетах ЮKassa, ККТ и ОФД.

## Код готов к проверке

- [x] Сумма и позиции чека строятся из рассчитанного сервером заказа, а не из цены браузера.
- [x] Телефон покупателя нормализуется для поля `receipt.customer.phone`.
- [x] Для товара передаются `vat_code: 1` («Без НДС»), `payment_mode: full_payment`, `payment_subject: commodity`.
- [x] Доставка передаётся отдельной строкой с `payment_subject: service`.
- [x] Сумма позиций и доставки сверяется с суммой платежа до запроса в ЮKassa.
- [x] В `provider_payload` сохраняется сокращённый ответ без Authorization и секретного ключа; payload очищается по retention через 30 дней после конечного статуса и закрытия заказа.
- [x] Webhook не доверяет входному статусу: платёж повторно проверяется у провайдера и применяется идемпотентно.

## Действия владельца и бухгалтера

- [ ] Договор и магазин ЮKassa активны; владелец получил `YOOKASSA_SHOP_ID` через защищённый канал.
- [ ] Новый `YOOKASSA_SECRET_KEY` получен через защищённый канал, не отправлен в чат/почту и не добавлен в Git.
- [ ] Бухгалтер подтвердил для ИП Цивилёва Павла Иннокентьевича режим «Без НДС» и применение `vat_code: 1` ко всем текущим позициям.
- [ ] ККТ зарегистрирована и привязана к интернет-магазину; адрес расчёта и сайт `https://pivdoner.ru` проверены в кабинетах.
- [ ] ОФД подключён; договор, регистрационные сведения кассы и срок действия проверены.
- [ ] Способ передачи чеков из ЮKassa в ККТ подтверждён по актуальной документации провайдера и кассового решения.
- [ ] Электронный чек уходит покупателю на телефон, указанный в заказе; тестовый чек получен и его реквизиты проверены бухгалтером.
- [ ] Номенклатура, количество, сумма товара и отдельная строка доставки совпали с тестовым заказом и чеком.
- [ ] Возврат и чек возврата проверены на тестовом платеже; ответственный знает порядок отмены.
- [ ] Секреты записаны только в `/opt/pivdoner/deploy/.env` на сервере с ограниченным доступом; резервные копии и логи их не печатают.
- [ ] Владелец письменно разрешил переключение с mock после успешной stage-приёмки.

## Переключение live

Только после всех пустых пунктов выше технический администратор заполняет `YOOKASSA_SHOP_ID` и `YOOKASSA_SECRET_KEY`, меняет `PAYMENT_PROVIDER=mock` на `PAYMENT_PROVIDER=yookassa`, перезапускает API и выполняет один контролируемый платёж. До этого live остаётся заблокированным. Реальные ключи в этот документ не записывать.

Перед настройкой сверить значения с актуальным [справочником параметров чеков ЮKassa](https://yookassa.ru/developers/payment-acceptance/receipts/54fz/other-services/parameters-values) и инструкцией выбранной ККТ. Справочник проверен 12 августа 2026 года; юридическую и бухгалтерскую применимость подтверждает владелец.
