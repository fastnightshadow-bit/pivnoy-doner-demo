## Фактическая матрица доступа

- `owner`: полный доступ существующих рабочих интерфейсов — агрегаты, настройки, стоп-лист и тот же staff API активных заказов.
- `kitchen`: staff API активных оплаченных заказов показывает имя, телефон, адрес, комментарии, позиции, цены/итоги, ETA и историю; интерфейс кухни использует эти сведения для приготовления и выдачи. Продавец не является отдельной ролью в коде и выполняет разрешённые операции через назначенную роль `kitchen`.
- `courier`: экран курьера использует только номер заказа, адрес, телефон и ETA/время готовности. Однако общий staff API технически возвращает этой роли более широкий набор активного заказа. Поэтому владелец обязан запретить использование лишних полей и не закрывать launch gate матрицы доступа, пока это ограничение не принято или API не сужен.
- Покупатель: только собственный заказ по id и секретному токену; ответ не содержит имя, телефон, адрес, комментарии и историю сотрудников.
- Публичный посетитель: каталог и только те отзывы, на публикацию которых дано отдельное действующее согласие.

## Ежедневное обслуживание

Сервис retention сначала допускает безопасный `--dry-run`, затем `--apply`. Он пишет только режим и агрегатные количества, без id, имён, телефонов, адресов, комментариев, токенов и ответов платёжного провайдера. Обычные сроки не заменяют отдельную обработку законного обращения покупателя.
